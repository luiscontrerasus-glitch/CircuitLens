# AI disclosure

Codex assisted with code, tests, debugging, documentation, research and original synthetic artwork generated by code. The runtime adapter uses the pretrained OpenAI model `gpt-4.1-mini-2025-04-14` via the Responses API for image perception. It proposes a structured observation object; electrical diagnoses and educational explanations are produced by deterministic JavaScript rules.

The runtime OpenAI vision request path is implemented, but successful live recognition is unverified. Five prior live requests on the synthetic inputs (correct three times, reversed once, disconnected once) returned HTTP 429; the provider diagnostic identified `credit_balance_exhausted` / `insufficient_quota`. No additional live requests were made during finalization. There are no saved successful model observations. Simulated perception is labeled explicitly in the development harness and its screenshots.

No fine-tuning, custom model weights or external labeled image dataset was used. Model confidence is uncalibrated. Every proposal needs confirmation or correction; unknown terminals, polarity or values cannot silently become verified circuit facts. Seven guided examples use disclosed fixture netlists. The three new visual inputs are synthetic labeled diagrams, not hardware photographs. Screenshots containing simulated perception are labeled on screen and in their filenames/captions.

Live analysis requires consent and sends resized image pixels through the server to OpenAI. The app does not persist user photos; `store:false` does not promise zero provider retention. Intended references never enter the perception request. Server secrets are excluded from browser files, builds and Git. A named CircuitLens key was provisioned in the selected Default project with a 30-day expiry; a separate dedicated project, restricted key permissions and provider spend cap were not configured. The application cap is 20 attempts/day and does not replace a billing cap.

AI assistance does not establish authorship dates or eligibility. The base workbench was committed September 30; preliminary uncommitted perception work also began that evening. The October 1 upgrade completed review/integration, validation, tests and packaging. See the shared build-period disclosure and the GIBC checklist for the conflicting deadline and post-cutoff commit concern.
